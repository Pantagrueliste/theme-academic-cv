AIコーディングアシスタントを使ってTEI XMLを書いたことがあれば、おそらく間違いが多いことに気づいたでしょう。要素があるべきでない場所に現れる。属性が捏造される。入れ子の規則が無視される。モデルはTEIがどのようなものかについて大まかな感覚は持っていますが、仕様についての信頼できる知識は持っていません。

tei-mcpは、AIエージェントにTEI P5ガイドラインへの直接的な、ツールベースのアクセスを与えることでこれを解決します。

## MCPとは何か

[Model Context Protocol](https://modelcontextprotocol.io)（MCP）は、AIアプリケーションが外部のデータソースやツールに接続できるようにするオープン標準です。AIのためのUSBポートのようなものと考えてください。Claude、Cursor、Windsurfなど、互換性のあるどのクライアントでも専門的なサービスに接続できる、単一のプロトコルです。

MCPサーバーは、AIが会話中に呼び出せる*ツール*を公開します。記憶した訓練データに頼る代わりに、モデルはライブの権威ある情報源に問い合わせることができます。

## tei-mcpの機能

tei-mcpはTEI P5のODD仕様を解析し、編集者やエンコーダーが尋ねる最も一般的な質問をカバーする16のツールを公開します。

- **この要素は何か？** 任意の要素、クラス、マクロ、モジュールを名前で検索します。大文字小文字を区別せず、タイプミスの候補も提示します。
- **どの属性を取るか？** クラス階層全体にわたって属性を解決します――まずローカルの属性、次に継承された属性を順に。
- **中に何を入れられるか？** 内容モデルを構造化された木に展開するか、有効な子要素の平坦なリストを取得します。
- **この要素はここに置けるか？** 親子の入れ子を確認するか、要素階層全体を通じた到達可能性を追跡します。
- **私の文書は妥当か？** TEI XMLファイルを仕様に照らして検証します。内容モデル、属性値、閉じた値リスト、参照の整合性、非推奨警告。
- **私のプロジェクトのスキーマは？** ODDカスタマイズファイルを読み込み、上記すべてをプロジェクト固有のTEIサブセットに制約します。

## なぜ重要か

TEIエンコーディングにはガイドラインの絶え間ない参照が必要です。経験豊富なエンコーダーは最も一般的なパターンを内面化していますが、彼らでさえ、なじみの薄い要素や複雑な内容モデルについては仕様を確認する必要があります。そうした内面化された知識を持たないAIアシスタントにとって、問題はより深刻です。もっともらしく見えるが誤ったマークアップをでっち上げてしまうのです。

tei-mcpがあれば、AIは推測する必要がありません。山括弧を一つ書く前に、仕様で答えを調べることができます。その結果は、TEI P5に――あるいはあなたのプロジェクトのODDカスタマイズに――準拠したマークアップです。

## はじめに

PyPIからインストールします。

```bash
pip install tei-mcp
```

次に、MCPクライアントの設定に追加します。

```json
{
  "mcpServers": {
    "tei": {
      "command": "uvx",
      "args": ["tei-mcp"]
    }
  }
}
```

サーバーは初回実行時にTEI仕様をダウンロードし、MCP互換のどのクライアントでも動作します。
