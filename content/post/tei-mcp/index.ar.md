إذا سبق لكم أن استخدمتم مساعد برمجة بالذكاء الاصطناعي لكتابة TEI XML، فلا بد أنكم 
لاحظتم أنه يخطئ. تظهر عناصر حيث لا ينبغي لها أن تظهر. وتُخترع سمات. 
وتُتجاهل قواعد التداخل. فلدى النموذج فكرة تقريبية عما تبدو عليه TEI، 
لكنه لا يملك معرفة موثوقة بالمواصفة.

يحل tei-mcp هذه المشكلة بمنح وكلاء الذكاء الاصطناعي وصولًا مباشرًا، قائمًا على الأدوات، إلى 
إرشادات TEI P5.

## ما هو MCP؟

[بروتوكول سياق النموذج (Model Context Protocol)](https://modelcontextprotocol.io) (MCP) معيار مفتوح 
يتيح لتطبيقات الذكاء الاصطناعي الاتصال بمصادر بيانات وأدوات خارجية. 
فكّروا فيه كمنفذ USB للذكاء الاصطناعي: بروتوكول واحد يتيح لأي 
عميل متوافق — Claude وCursor وWindsurf وغيرها — أن يتصل 
بخدمات متخصصة.

يعرض خادم MCP *أدوات* يمكن للذكاء الاصطناعي استدعاؤها في أثناء المحادثة. 
فبدلًا من الاعتماد على بيانات تدريب محفوظة، يستطيع النموذج الاستعلام من مصدر 
حي وموثوق.

## ما الذي يفعله tei-mcp

يحلّل tei-mcp مواصفة TEI P5 بصيغة ODD ويعرض 16 أداة تغطي 
أكثر الأسئلة شيوعًا التي قد يطرحها محقق أو مرمّز:

- **ما هذا العنصر؟** ابحثوا عن أي عنصر أو صنف أو ماكرو أو وحدة (module) 
  بالاسم، مع مطابقة غير حساسة لحالة الأحرف واقتراحات لتصحيح الأخطاء الإملائية.
- **ما السمات التي يقبلها؟** حلّوا السمات عبر التسلسل الهرمي الكامل 
  للأصناف — السمات المحلية أولًا، ثم الموروثة بالترتيب.
- **ما الذي يمكن أن يُدرج داخله؟** وسّعوا نماذج المحتوى إلى أشجار مهيكلة، 
  أو احصلوا على قائمة مسطحة بالعناصر الأبناء الصالحة.
- **هل يجوز وضع هذا العنصر هنا؟** تحققوا من تداخل الأصل والفرع، أو تتبّعوا 
  إمكانية الوصول عبر التسلسل الهرمي الكامل للعناصر.
- **هل وثيقتي صالحة؟** تحققوا من صحة ملف TEI XML مقابل المواصفة: نماذج 
  المحتوى، وقيم السمات، وقوائم القيم المغلقة، وسلامة المراجع، 
  وتحذيرات الإهمال (deprecation).
- **وماذا عن مخطط مشروعي؟** حمّلوا ملف تخصيص ODD 
  لتقييد كل ما سبق بالمجموعة الفرعية الخاصة بمشروعكم من TEI.

## لماذا يهم هذا الأمر

يتطلب الترميز بـTEI رجوعًا دائمًا إلى الإرشادات. فالمرمّزون ذوو الخبرة 
يستبطنون الأنماط الأكثر شيوعًا، لكن حتى هم يحتاجون إلى مراجعة 
المواصفة للعناصر الأقل ألفة أو نماذج المحتوى المعقدة. أما مساعدو 
الذكاء الاصطناعي، الذين لا يملكون معرفة مستبطنة من هذا القبيل، فالمشكلة لديهم أسوأ: 
إنهم يهلوسون ترميزًا يبدو معقولًا لكنه غير صحيح.

مع tei-mcp، لا يضطر الذكاء الاصطناعي إلى التخمين. فبإمكانه البحث عن الجواب في 
المواصفة قبل كتابة قوس زاوية واحد. والنتيجة ترميز 
يتوافق مع TEI P5 — أو مع تخصيص ODD الخاص بمشروعكم.

## البدء

ثبّتوه من PyPI:

```bash
pip install tei-mcp
```

ثم أضيفوه إلى إعدادات عميل MCP لديكم:

```json
{
  "mcpServers": {
    "tei": {
      "command": "uvx",
      "args": ["tei-mcp"]
    }
  }
}
```

ينزّل الخادم مواصفة TEI عند التشغيل الأول ويعمل مع أي 
عميل متوافق مع MCP.
