当我[第一次介绍tei-mcp](/post/tei-mcp/)时，目标是阻止AI助手幻觉出TEI标记。模式锚定解决了问题的一部分：有了对P5规范的直接、基于工具的访问，模型不再需要猜测某个元素的含义或它接受哪些属性。输出能够通过验证。

但在TEI编码中，幻觉有两副面孔，而模式只能抓住其中一副。依据规范验证只能告诉您*标记*是否格式良好。它对标记所包裹的*文本*不置一词。而正是这里——文本本身——潜藏着更具破坏性的幻觉。v0.3的头号新功能区间锁定合成（span-locked composition），正是专门为防止这类幻觉而设计的。

## 模式抓不住的幻觉

让模型编码一封十六世纪的法文信件，您往往会得到一份看起来无可挑剔的TEI文档。头部填写完整，`<persName>`标签位置正确，`<dateline>`格式良好。用`validate_document`跑一遍，通过。

然后把正文与源文本做一下比对。

`mesme`变成了`même`。一个逗号挪了位置。`luy`被悄悄现代化为`lui`。手稿中一处难以辨认的分句被“修正”成了更通顺的东西。这些改动没有一处是被要求的。没有一处被标记出来。文档在模式上有效，却悄无声息地错了。

对于档案工作流——编码后的文本将成为下游读者、搜索索引和引用所依赖的永久记录——这是最要紧的失效模式。一个格式错误的标签令人烦恼。一个五年无人察觉的现代化拼写则是一处讹误。

## 区间锁定合成

新版本（v0.3）附带了一个直指这一失效模式的幻觉防范机制。设计目标是让正文幻觉从构造上就不可能发生，而不仅仅是不太可能。

思路很简单：**模型从不键入正文**。

相反，工作流是这样的：

1. 模型调用`get_source("letter_001")`，接收作为不可变字符串的源纯文本。
2. 对于它想施加的每一个标签，它调用`tag_span("letter_001", start, end, element_path, attrs)`——在源文本的某个字符区间上登记一个TEI元素。
3. 完成后，它调用`compose("letter_001")`。服务器将登记的标签与原始纯文本交织起来，渲染出最终的TEI，然后*逐字节*验证渲染文档的扁平文本内容等于源文本。

字节匹配，文档就返回。若不匹配——如果模型的标签以某种方式暗示了一个与源文本哪怕相差一个字符的正文——`compose()`就会抛出异常，而不是返回一份文本已受损的文档。

在这个工作流中，不存在任何一条路径能让模型产出正文与源文本不同的TEI文档。这一不变量是机械性的，而非行为性的。您不必信任模型不会幻觉；您只需信任两个字节串之间的一次`==`检查。

## 它是什么，不是什么

区间锁定合成是对模式锚定的**补充**，而非替代。模式锚定工具（`validate_document`、`lookup_element`、`valid_children`以及最初十六个工具中的其余部分）帮助模型产出*有效*的TEI。区间锁定合成则保证该TEI中的正文*忠实*于源文本。一个可部署的编码工作流必须同时满足这两个维度，而现在两者都由同一个服务器覆盖。

它也不是包治百病的灵药。`compose()`尚未检查登记的标签是否被已加载的ODD定制所允许——这是后续工作。登记的标签存放在进程内存中，重启后不会保留。而且源文件必须能从服务器运行的位置读取。这些都是可以解决的；没有一项会动摇核心不变量。

## 为什么这在TEI之外也有意义

这一模式可以推广。任何时候，当模型被要求注释、转换或包裹一段文本——而且底层文本的完整性比模型“改进”它的能力更重要——同样形态的解决方案都适用。不要让模型重新键入文本。让它在文本之上生成指令，再由一个确定性的合成器在相等性不变量的约束下执行这些指令。

具体到数字版本，这改变了您可以负责任地交给模型去做的事情。编码突然变成了一项可以委托的任务，而不必手动比对每一份输出与源文本。机器走枯燥的那条路；编辑者审阅的是标记，而不是拼写。

## 获取更新

如果您已经安装了tei-mcp：

```bash
uvx tei-mcp@latest
```

或者全新安装：

```bash
pip install tei-mcp
```

要使用区间锁定合成，请将服务器指向一个存放源纯文本文件的目录：

```bash
export TEI_MCP_SPAN_SOURCE_ROOT=/path/to/sources
uvx tei-mcp
```

每个文件的主名即为其文档ID（`letter_001.txt` →
`letter_001`）。

源代码、完整文档以及该不变量的设计说明：
[github.com/Pantagrueliste/tei-mcp](https://github.com/Pantagrueliste/tei-mcp)
