2007年ごろ、当時ニューサウスウェールズ大学の学生だったヨセ・ウィジャヤ（Yose Widjaja）は、ネットワークを三次元で探索するための見事なプログラム、Skyrailsを作りました。使う人はネットワークそのものの中を、光るレールに沿ってノードからノードへと旅していく。まるでデータの内側にいるかのように。研究用のツールといえばたいてい平板で灰色だった時代に、それはビデオゲームのように見えました。しかも見た目の奥には、確かな中身がありました。Skyrailsはグラフの見た目を整え、分析するための独自のスクリプト言語を備え、メニューもその言語で書かれていたので、プログラミングのできない人でも使えたのです。これをすべて、ひとりの学生が成し遂げていました。何年も前にYouTubeでデモを見て以来、私はずっとそれを忘れられずにいます。


## 消えたプログラム

Skyrailsが保守されることは、ついにありませんでした。Windows用のソフトで、大学にあったホームページは消え、たどったリンクはことごとく切れていました。残っていたのは痕跡です。Flickrの[スクリーンショットのアルバム](https://www.flickr.com/photos/14933315@N05/albums/72157602730584157/)と、2007年に書かれた一握りのブログ記事。[FlowingData](https://flowingdata.com/?p=947)、ティム・ランバート（Tim Lambert）の[*Deltoid*](https://scienceblogs.com/deltoid/2007/10/22/skyrails-graph-visualizations)、そして[InfoVis Wiki](https://infovis-wiki.net/wiki/2007-10-27:_Skyrails:_Social_Network_Visualisation_System)に載ったものです。

スクリーンショットは、思いのほか多くを語ってくれます。雲の筋が走る濃紺の夜空、動く山形模様（シェブロン）で描かれたエッジ、アイコンや円グラフの形をしたノード、そしてマウスの右ボタンを押したままにするとノードの周りに開く放射状のメニュー。各デモを動かしていたスクリプトの名前（`labs.van`、`macaque.van`、`worldtrade.van`）も、それらのスクリプトが作り出したメニューも、*normal*、*desert*、*valley*、*openspace*という四つのテーマも写っています。なかには、画面上部のコンソールに打ち込まれたスクリプト言語の一行を、そのまま留めているものさえあります。

```
with all nodes do nodeplane x 1 -1 end
```


## 手がかりから組み直す

これらの手がかりをもとに、Claudeは一晩でSkyrailsを再建しました。新しい版は[Three.js](https://threejs.org/)を使ってウェブブラウザ上で動き、理屈の上では、VRヘッドセットでも動くはずです。写し取ったのは、空、山形模様のレール、アイコンや円グラフやリングをまとって光るノード、ポインターを合わせたノードに出る大きなラベル、放射状のメニュー、そして四つのテーマ。スクリーンショットに残された一行を軸に組み立てた小さなスクリプト言語もあり、`with … do … end`文でグラフの見た目を整え、メニューを定義できます。

試しに、古典的なデータセットを三つ読み込んでみました。婚姻と商売の結びつきをたどった、ジョン・パジェット（John Padgett）によるフィレンツェの名家のネットワーク。ウェイン・ザカリー（Wayne Zachary）の空手クラブ。そして、ドナルド・クヌース（Donald Knuth）による『レ・ミゼラブル』の登場人物のネットワークです。こちらでは、同じ章に登場する二人の人物が線で結ばれます。下の動画は、この最後のネットワークの中を、ジャン・ヴァルジャンからジャヴェール、ファンチーヌ、コゼット、マリユスへと旅していきます。カメラがたどるにつれて、レールが一本ずつ光ります。

出来上がりがあまりにスクリーンショットそっくりだったので、私はすぐに、オリジナルのコードの痕跡が訓練の過程でモデルに取り込まれていたのではないかと疑いました。


## 本物が現れる

ところが、話はここで思わぬ方向に転がります。再建を終えたあと、GitHubでオリジナルのプログラムが見つかったのです。2015年、ある研究者がヨセ・ウィジャヤの許可を得て、セキュリティ会議ShmooConで行ったデータ可視化の講演のコードと一緒に公開していました（[RITHoneynet/DataVisualization](https://github.com/RITHoneynet/DataVisualization)。[Light0617/3D_UIUX](https://github.com/Light0617/3D_UIUX/tree/master/skyrails/skyrailsdist)にも複製があります）。Windowsの実行ファイル、データ、シェーダー、オリジナルのスクリプトは入っていますが、本体エンジンのソースコードはありません。

これで両者を比べられるようになりました。再建版は、見た目と操作感ではオリジナルにかなり迫っていましたが、スクリプト言語とシェーダーはまるで別物です。オリジナルのスクリプトは、たとえばこんな具合です。

```
with all edges do (
   if(#marriage == 1) then (
      linkorigin <- marriage -> linktarget;
   ) end;
) end;
```

サブルーチンは`sub`で、メニューは`menudef`と`menulink`で、色は`rgb: 130 0 0`で定義し、リンクの種類は矢印で定義します。再建版にはそのどれも現れず、共通しているのは、スクリーンショットに見えていた`with … do … end`の形だけです。`BloomFX`や`RetinalBurnFX`といった名前のオリジナルのシェーダーも、新しいシェーダーとは何ひとつ共通点がありません。

だからといって、モデルが記憶していたのかどうかという問いに決着がつくわけではありません。オリジナルのスクリプトは2015年から公開されており、モデルの訓練データに含まれていた可能性は十分にあります。そして、モデル自身も含めて、それが何を目にしてきたのかを確かに言える者は誰もいません。それでも、もしモデルがSkyrailsを記憶していたのなら、少なくとも言語くらいは再現していたはずだと私は思います。これらの違いは、Claudeがスクリーンショットに残された手がかりをもとに仕事をしたことをうかがわせます。


## デジタル考古学とソフトウェアの持続可能性

私はこの実験を、一種のデジタル考古学だと考えています。失われた物を、それが残した痕跡から組み直し、そのあとでオリジナルを見つけて、どこまで迫れていたかを測る。どんな復元もそうであるように、新しいSkyrailsもひとつの解釈です。見た目とふるまいは証拠に拠っていますが、その下にあるものはすべて新しく作られています。

これは持続可能性の問題でもあります。ソフトウェアは、それが読むために作られたデータよりも、はるかに速く古びていきます。プログラムが死ねば、それを使って作られたファイルもスクリプトも可視化も、たとえ残っていたとしても開くのが難しくなる。2000年代のソフトウェアの多くは、いまやスクリーンショットと動画、そして動かせるマシンが年々減っていく古いバイナリとしてしか存在しません。オリジナルのSkyrailsは、Windowsのパソコンやエミュレーターの上でなら、まだ起動するかもしれません。けれどもソースコードが失われた以上、保守することも、手を加えることも、移植することも、もうできないのです。

数年前に私が予想したとおり、AIはこの種の陳腐化に対抗する実用的な道具になりつつあります。失われたツールをその痕跡から再建することもできれば、古いデータを使える状態に保つための読み込みプログラムを作り直すこともできます。このプロジェクトの次の一歩は、はっきりしています。新しいエンジンに、オリジナルの`.van`スクリプトとデータファイルを読めるよう教え込み、ヨセ・ウィジャヤが2007年に書いたデモをふたたび動かすことです。研究であれ、アーカイブであれ、デジタル・ヒューマニティーズであれ、データの持続可能性を気にかけるすべての人にとって、これは注目に値することです。

Skyrailsは時代の先を行っていました。二十年近くたったいまも、見る者を唸らせます。アイデアとデザインの功績は、すべてヨセ・ウィジャヤのものです。この記事が彼のもとに届くことを願っています。
